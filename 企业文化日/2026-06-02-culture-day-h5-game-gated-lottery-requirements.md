# 企业文化日 H5 小游戏达标后抽奖需求方案

> 版本：v1.0  
> 日期：2026-06-02  
> 适用场景：员工需参与线上小游戏并达到当轮条件后，才可获得当轮抽奖机会。  
> 核心规则：4 个抽奖时段；每轮最多抽 1 次；全活动每人最多中奖 1 次；允许员工 4 轮均未中奖。

## 1. 背景与目标

企业文化日活动期间，通过 H5 面向全员开放线上互动。员工在指定时间进入 H5，完成身份校验后参与小游戏。每个抽奖时段对应一轮小游戏任务，员工达到当轮积分或完成条件后，获得该轮抽奖资格。

本方案目标：

- 提升员工参与感，不只是“点一下抽奖”，而是通过小游戏形成互动。
- 支持 4 个不同时间节点的抽奖节奏，配合线下活动氛围。
- 控制中奖公平性：每名员工全活动最多中奖 1 次。
- 支持“未中奖”结果，员工即使参与 4 轮也可能不中。
- 沉淀登录、参与、达标、抽奖、中奖、领奖数据，便于复盘。

## 2. 核心规则

| 规则项 | 要求 |
| --- | --- |
| 参与对象 | 公司员工，需在员工名单内 |
| 登录方式 | 手机号登录，绑定唯一员工身份 |
| 抽奖轮次 | 共 4 轮，按不同时间段开放 |
| 每轮机会 | 员工每轮最多获得 1 次抽奖机会 |
| 获得机会条件 | 登录后参与小游戏，并达到当轮积分门槛或完成条件 |
| 中奖上限 | 每名员工全活动最多中奖 1 次 |
| 不中规则 | 每次抽奖都允许出现未中奖结果 |
| 已中奖员工 | 后续轮次可继续玩小游戏，但不再参与中奖池 |
| 奖品库存 | 每轮独立配置奖品数量，可选择未发完滚入后续轮次 |

## 3. 四轮抽奖配置

| 轮次 | 建议场景 | 开放时间 | 参与条件 | 抽奖状态 |
| --- | --- | --- | --- | --- |
| 第 1 轮 | 开幕热身 | 活动开始前后 | 完成小游戏并达标 | 达标后可抽 |
| 第 2 轮 | 上午互动 | 上午项目期间 | 完成小游戏并达标 | 达标后可抽 |
| 第 3 轮 | 下午冲刺 | 下午项目期间 | 完成小游戏并达标 | 达标后可抽 |
| 第 4 轮 | 闭幕终极抽奖 | 闭幕前后 | 完成小游戏并达标 | 达标后可抽 |

每轮需支持独立配置：

- 开始时间、结束时间
- 游戏积分门槛或完成条件
- 是否允许重复挑战小游戏
- 奖品池、奖品数量、中奖概率或中奖名额
- 未发完奖品是否滚入后续轮次

## 4. 员工端 H5 需求

### 4.1 活动首页

- 展示活动名称、主视觉、当前轮次、下一轮时间。
- 展示当前登录员工状态：未登录、已登录、已中奖、未中奖、待抽奖。
- 展示当前轮次小游戏入口。
- 展示当前轮次抽奖入口，未达标时不可点击或提示需先完成小游戏。
- 展示“我的奖品”“活动规则”“领奖说明”入口。

### 4.2 登录与身份校验

- 员工输入手机号登录。
- 系统校验手机号是否在员工名单内。
- 一个手机号只能绑定一个员工。
- 一个员工只能生成一个参与身份。
- 登录失败时展示明确原因，如“不在活动名单内”“手机号异常”“账号已冻结”。

### 4.3 小游戏

- 每轮可使用相同玩法，也可更换素材、文案或积分门槛。
- 游戏结束后展示当轮得分或完成状态。
- 达标时提示“已获得本轮抽奖资格”。
- 未达标时提示“暂未获得本轮抽奖资格”，并说明是否可再次挑战。
- 已中奖员工可继续体验小游戏，但需明确提示“不再获得新的中奖机会”。

### 4.4 抽奖

- 员工进入抽奖页时，系统再次校验：
  - 是否已登录
  - 是否处于当前轮次开放时间
  - 是否完成当轮小游戏并达标
  - 是否已抽过本轮
  - 是否已在前序轮次中奖
  - 当前奖品池是否仍有库存
- 员工点击抽奖后，展示中奖或未中奖结果。
- 无论中奖或未中奖，都需记录该轮抽奖结果。
- 已抽过本轮的员工再次进入时展示原结果，不可重复抽。

### 4.5 我的奖品

- 展示中奖轮次、奖品名称、中奖时间、领奖方式、领奖状态。
- 支持展示核销码或领奖凭证。
- 未中奖员工可展示“暂无中奖记录”。

## 5. 运营后台需求

本方案建议至少建设轻量运营后台，否则 4 轮时间控制、小游戏门槛、中奖排重和奖品核销都很难稳定操作。

后台需支持：

- 员工名单导入、异常名单查看、员工状态查询。
- 活动基础信息配置：活动名称、活动时间、规则文案、客服联系方式。
- 4 轮抽奖配置：开放时间、关闭时间、小游戏门槛、轮次状态。
- 奖品配置：奖品名称、图片、等级、数量、所属轮次、领奖说明。
- 中奖限制配置：全活动每人最多中奖 1 次。
- 抽奖记录查看：每轮参与人数、达标人数、抽奖人数、中奖人数、未中奖人数。
- 中奖名单导出：按轮次、部门、员工、奖品维度导出。
- 领奖核销：标记待领取、已领取、作废、异常。
- 操作日志：记录配置变更、名单调整、奖品数量调整和人工处理。

## 6. 是否必须要运营后台

结论：建议需要，至少需要“轻量运营后台 + 数据导出 + 核销能力”。

原因：

- 4 个不同时间段开放，运营需要能临时调整开始/结束时间。
- 小游戏门槛、奖品库存、未发完奖品滚入后续轮次都需要配置。
- “每人最多中奖一次”必须依赖统一中奖记录排重，不能只靠前端判断。
- 需要处理员工手机号异常、员工名单漏导、离职或调岗等问题。
- 活动现场通常会出现领奖核销、中奖名单导出、临时补录等运营动作。

可降级方案：

- 若工期很紧，可不做完整后台 UI。
- 但仍需保留服务端配置、数据库记录、导入脚本、导出脚本和人工核销表。
- 该降级方案适合运营动作少、活动规则不变、现场不需要频繁调整的情况。

## 7. 异常与边界

| 场景 | 处理要求 |
| --- | --- |
| 员工不在名单内 | 不允许参与抽奖，引导联系活动组 |
| 当前轮次未开始 | 展示下一轮开放时间 |
| 当前轮次已结束 | 不允许补抽，除非后台人工处理 |
| 小游戏未达标 | 不允许进入抽奖 |
| 员工已抽过本轮 | 展示本轮原抽奖结果 |
| 员工已中奖 | 后续轮次不再进入中奖池 |
| 奖品库存为 0 | 展示未中奖或奖品已抽完 |
| 配置变更 | 不影响已产生的抽奖和中奖记录 |
| 网络中断 | 以前端拿到服务端最终记录为准 |

## 8. 验收标准

- 员工可完成登录、小游戏、达标、抽奖、查看结果的完整流程。
- 每轮抽奖只在配置时间内开放。
- 未达标员工不能抽奖。
- 同一员工同一轮不能重复抽奖。
- 同一员工全活动最多中奖 1 次。
- 员工参与 4 轮后仍可能 0 次中奖。
- 中奖记录、未中奖记录、领奖记录均可查询和导出。
- 后台可完成员工名单、4 轮时间、奖品池、中奖名单和领奖状态管理。
