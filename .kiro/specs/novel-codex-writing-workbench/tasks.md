# 小说 Codex 创作工作台任务拆分

## 实施任务

- [x] 1. 创建规格文档和执行计划
  - 保存需求文档、设计文档、任务文档和详细实施计划
  - 明确第一版 MVP 范围，不把桌面封装、多人协作和复杂知识库纳入第一阶段
  - 验收：`.kiro/specs/novel-codex-writing-workbench/` 和 `docs/plans/` 下存在对应文档
  - _需求：11.1, 11.2, 11.3_

- [x] 2. 梳理现有 UI 和服务基础
  - 检查 `ui/src/App.vue`、`ui/src/services/api.ts`、`ui/src/stores/` 的可复用部分
  - 判断当前项目是否已有 Node API 服务可承接小说工作台接口
  - 输出一份实现前技术盘点，标记要复用、要改造和要新增的模块
  - 验收：形成技术盘点记录，并确认第一版入口放在现有 UI 还是新建模块
  - _需求：10.1, 11.3_

- [x] 3. 定义小说项目文件结构
  - 创建项目文件模型，包括 `project.json`、`bible/`、`outline/`、`chapters/`、`ledger/` 和 `tasks/`
  - 实现项目 slug、文件路径和章节编号规则
  - 增加路径安全校验，禁止任务读写项目目录之外的文件
  - 验收：可以创建一个空小说项目目录，并生成默认文件
  - _需求：1.3, 2.1, 3.1_

- [x] 4. 实现 Codex CLI 配置检测
  - 增加 Codex CLI 路径配置、版本检测和可用性检测
  - 支持默认使用 `codex`，也支持用户配置绝对路径
  - Codex 不可用时返回明确错误
  - 验收：mock 可用和不可用两种 Codex CLI 状态均能得到正确结果
  - _需求：8.1, 8.4_

- [x] 5. 实现写作任务模板注册表
  - 定义 `project.create`、`outline.generate`、`chapter.plan`、`chapter.draft`、`selection.polish`、`continuity.check`、`idea.suggest`
  - 每个模板包含输入字段、上下文策略、系统提示、输出 JSON schema
  - 支持后续新增任务类型
  - 验收：给定任务类型和输入，能生成稳定的 Codex CLI prompt 文件
  - _需求：8.1, 8.2_

- [x] 6. 实现上下文组装器
  - 按任务类型读取故事圣经、章纲、相邻章节摘要、伏笔账本和升级进度
  - 对长章节做摘要或截断，保留关键事实
  - 对选区润色只注入必要上下文，避免污染局部改写
  - 验收：每类任务都能输出包含正确上下文块的 prompt
  - _需求：2.2, 5.2, 6.2, 8.2_

- [x] 7. 实现 Codex CLI 任务执行器
  - 使用子进程调用 Codex CLI
  - 记录任务开始、结束、退出码、stdout、stderr 和耗时
  - 支持取消任务和失败重试
  - 验收：使用 mock Codex CLI 可以跑通任务创建、执行、完成和失败流程
  - _需求：8.3, 8.4, 10.3_

- [x] 8. 实现结构化输出解析
  - 解析 Codex 返回的 JSON 结果
  - 输出解析失败时保留原始文本并标记错误
  - 支持 `content`、`changes`、`risks`、`questions`、`patches` 字段
  - 验收：正常 JSON、包裹在 Markdown 代码块中的 JSON、非法 JSON 都有测试覆盖
  - _需求：5.3, 8.3, 9.3_

- [x] 9. 实现项目创建流程
  - 前端提供粗略想法输入
  - 后端调用 `project.create`
  - 成功后生成故事圣经、大纲草案、章节目录和写作配置
  - 验收：输入一句粗略创意后能创建完整项目文件夹
  - _需求：1.1, 1.2, 1.3, 2.1_

- [x] 10. 实现故事圣经编辑与注入
  - 前端展示角色、世界观、力量体系、地点和风格规则
  - 支持保存修改
  - 后续任务自动读取最新故事圣经
  - 验收：修改角色设定后，下一次章纲或润色任务 prompt 包含新设定
  - _需求：2.1, 2.2, 2.4_

- [x] 11. 实现大纲与情节链工作台
  - 显示卷纲、章纲、章节因果链和伏笔信息
  - 支持调用 `outline.generate` 生成或重写大纲
  - 支持把作者反馈传给 Codex CLI 做局部调整
  - 验收：能从故事圣经生成卷纲和前若干章章纲
  - _需求：3.1, 3.2, 3.3, 3.4_

- [x] 12. 实现升级节奏账本
  - 保存当前能力、下一阶段能力、触发条件、代价、限制和副作用
  - 在章节规划和连续性检查中注入升级信息
  - 标记提前开挂或升级代价缺失的风险
  - 验收：当草稿中出现未获得能力时，连续性检查能标记问题
  - _需求：4.1, 4.2, 4.3_

- [x] 13. 实现章节规划功能
  - 前端选择章节后调用 `chapter.plan`
  - 生成本章目标、场景卡、冲突、转折、结尾钩子
  - 支持保存到对应 `outline/chapter-xxx.md`
  - 验收：选择章节并点击规划后，章纲文件被生成或更新
  - _需求：5.1, 5.2_

- [x] 14. 实现章节正文起草功能
  - 基于章纲、故事圣经、相邻章节和文风规则调用 `chapter.draft`
  - 返回正文、风险和修改建议
  - 作者确认后写入 `chapters/chapter-xxx.md`
  - 验收：可以从章纲生成一章草稿，并在确认后保存
  - _需求：5.2, 5.3, 5.4_

- [x] 15. 实现正文编辑器基础能力
  - 显示章节树和 Markdown 正文
  - 支持打开、编辑、保存章节
  - 保留撤销、保存状态和未保存提示
  - 验收：作者可以手动编辑章节并保存到项目文件
  - _需求：10.1, 10.2_

- [x] 16. 实现选区润色操作
  - 捕获编辑器选区
  - 支持润色、扩写、压缩、降低浮夸、增强压迫感、修复逻辑跳跃、POV 检查
  - 调用 `selection.polish`
  - 验收：选中文字后可以得到改写结果，但不会自动替换原文
  - _需求：6.1, 6.2, 6.3_

- [x] 17. 实现选区结果对比与应用
  - 展示原文和改写结果
  - 支持接受、拒绝、再次调整
  - 当结果改变剧情事实时显示确认提示
  - 验收：接受后只替换原选区，拒绝后正文不变
  - _需求：6.3, 6.4, 10.3_

- [x] 18. 实现灵感补充功能
  - 基于当前章节、大纲、伏笔、人物矛盾和升级阶段调用 `idea.suggest`
  - 输出下一章事件、冲突反转、伏笔安排、人物互动和小危机
  - 支持把选中的灵感转成章纲或场景卡
  - 验收：没思路时能生成至少五类可用候选，并可写入章纲
  - _需求：7.1, 7.2, 7.3, 7.4_

- [x] 19. 实现连续性检查
  - 调用 `continuity.check`
  - 检查人物动机、时间线、地点、道具、能力、伏笔和 POV 边界
  - 按严重程度输出问题
  - 验收：给定一个有明显前后矛盾的 mock 章节，系统能标出问题和修复建议
  - _需求：9.1, 9.2, 9.3, 9.4_

- [x] 20. 实现任务历史与审计记录
  - 保存每次 Codex CLI 调用的任务类型、输入摘要、输出摘要、错误和耗时
  - 支持在 UI 查看最近任务
  - 不保存敏感环境变量
  - 验收：完成一次大纲生成和一次润色后，历史记录可查询
  - _需求：8.4, 10.3_

- [x] 21. 编写自动化测试
  - 后端测试任务模板、上下文组装、Codex 执行器、输出解析、路径安全
  - 前端测试项目创建、章节编辑、选区润色、结果应用
  - 集成测试使用 mock Codex CLI
  - 验收：测试命令可以稳定通过，不依赖真实 Codex 网络或模型输出
  - _需求：全部_

- [x] 22. 编写使用文档和故障排查
  - 说明如何配置 Codex CLI
  - 说明如何创建项目、生成大纲、规划章节、选区润色和连续性检查
  - 记录常见错误，如 Codex 不可用、JSON 解析失败、上下文过长
  - 验收：新用户可以按文档完成一次从创意到章节草稿的流程
  - _需求：11.3, 11.4_

- [x] 23. MVP 手工验收
  - 使用一个测试创意创建小说项目
  - 生成故事圣经、卷纲、章纲
  - 起草一章正文
  - 对指定选区润色并应用
  - 运行连续性检查
  - 验收：完整流程可用，且所有关键文件都被正确保存
  - _需求：1.1-11.4_
