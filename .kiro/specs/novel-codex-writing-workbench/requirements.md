# 小说 Codex 创作工作台需求文档

## 介绍

本需求用于设计一个调用 Codex CLI 的小说创作辅助软件。作者只需要提供粗略想法，系统能够帮助生成故事圣经、大纲、章节规划、环环相扣的情节、伏笔账本、升级节奏，并支持在正文编辑时对指定选区进行润色、扩写、压缩、查错和灵感补充。

系统定位不是“替作者一次性乱写正文”，而是“长篇小说结构编辑 + 连续性编辑 + 文风润色助手”。核心价值是帮助作者维护因果、人物动机、POV 边界、伏笔回收和逐步升级的可信节奏。

## 需求

### 需求 1：项目创建与创作入口

**用户故事：** 作为小说作者，我希望只输入粗略创意，系统就能帮我整理成可继续发展的作品项目，以便快速开始构思长篇小说。

#### 验收标准

1. WHEN 作者输入一句话或几段粗略设定 THEN 系统 SHALL 生成项目名称、题材、核心卖点、主角初始状态、主要矛盾和故事基调。
2. WHEN 粗略设定缺少关键要素 THEN 系统 SHALL 最多提出 3 个关键补充问题，而不是连续追问过多信息。
3. WHEN 作者确认生成结果 THEN 系统 SHALL 创建作品项目结构，并保存故事圣经、大纲、章节目录和写作配置。
4. IF 作者不满意生成结果 THEN 系统 SHALL 支持基于作者反馈重新生成或局部修改。

### 需求 2：故事圣经管理

**用户故事：** 作为小说作者，我希望系统能维护世界观、角色、力量体系和文风规则，以便后续写作不偏离设定。

#### 验收标准

1. WHEN 创建项目成功 THEN 系统 SHALL 生成并保存角色档案、世界观规则、力量体系、重要地点、风格约束和禁忌事项。
2. WHEN 作者修改故事圣经 THEN 系统 SHALL 在后续 Codex CLI 调用中自动注入最新设定。
3. WHEN 系统生成正文或建议 THEN 系统 SHALL 遵守角色当前认知，不让角色知道其 POV 内不可能知道的信息。
4. WHEN 设定存在冲突 THEN 系统 SHALL 标记冲突位置并给出修正建议，而不是直接覆盖原设定。

### 需求 3：大纲与情节链

**用户故事：** 作为小说作者，我希望系统能从粗略创意生成卷纲、章纲和情节因果链，以便故事发展环环相扣。

#### 验收标准

1. WHEN 作者请求生成大纲 THEN 系统 SHALL 输出卷级目标、阶段矛盾、关键转折、章节列表和结局方向。
2. WHEN 生成章纲 THEN 系统 SHALL 为每章记录起因、冲突、选择、后果、伏笔、回收点和人物变化。
3. WHEN 新章节规划与既有大纲冲突 THEN 系统 SHALL 提醒作者冲突内容并提供至少 2 种调整方案。
4. WHEN 作者调整大纲 THEN 系统 SHALL 支持同步更新受影响的伏笔账本、升级节奏和章节计划。

### 需求 4：升级节奏控制

**用户故事：** 作为长篇小说作者，我希望主角成长和能力升级是一步一步发生的，以便避免浮夸、突兀和开挂感。

#### 验收标准

1. WHEN 系统生成成长线 THEN 系统 SHALL 记录当前能力、下一阶段能力、触发条件、获得代价、限制和副作用。
2. WHEN Codex CLI 生成章节正文 THEN 系统 SHALL 检查主角是否提前使用未获得的能力。
3. WHEN 需要安排升级剧情 THEN 系统 SHALL 优先生成由困境、选择、代价和后果推动的升级，而不是无代价奖励。
4. IF 作者要求更爽快的升级 THEN 系统 SHALL 可以提高节奏，但仍需保留限制、成本或后续反噬。

### 需求 5：章节规划与正文起草

**用户故事：** 作为小说作者，我希望系统先规划单章场景，再生成正文，以便每章都有明确目标和推进作用。

#### 验收标准

1. WHEN 作者选择某一章并请求规划 THEN 系统 SHALL 生成本章目标、场景列表、冲突点、转折点、结尾钩子和需要承接的前文。
2. WHEN 作者请求起草正文 THEN 系统 SHALL 基于本章规划、故事圣经、相邻章节摘要和风格规则调用 Codex CLI。
3. WHEN 正文生成完成 THEN 系统 SHALL 返回正文、生成说明、潜在风险和可选修改方向。
4. WHEN 正文与已有设定或前后章节不一致 THEN 系统 SHALL 标记问题并建议修订。

### 需求 6：选区润色与局部改写

**用户故事：** 作为正在写作的作者，我希望选中一段文字后直接润色、扩写、压缩或改风格，以便快速改善局部文本。

#### 验收标准

1. WHEN 作者选中正文片段 THEN 系统 SHALL 显示可用操作，包括润色、扩写、压缩、降低浮夸、增强压迫感、修复逻辑跳跃和 POV 检查。
2. WHEN 作者执行选区操作 THEN 系统 SHALL 只把选区文本、必要上下文和相关设定传给 Codex CLI。
3. WHEN Codex CLI 返回结果 THEN 系统 SHALL 提供原文与改写结果对比，并允许接受、拒绝或再次调整。
4. IF 选区改写会改变剧情事实 THEN 系统 SHALL 明确提示作者确认。

### 需求 7：灵感补充

**用户故事：** 作为小说作者，我希望没思路时系统能基于当前剧情提供可用灵感，以便继续推进创作。

#### 验收标准

1. WHEN 作者请求灵感 THEN 系统 SHALL 基于当前章节、大纲、伏笔、人物矛盾和升级阶段生成建议。
2. WHEN 生成灵感 THEN 系统 SHALL 至少提供下一章事件、冲突反转、伏笔安排、人物互动和小危机五类候选。
3. WHEN 作者选择某个灵感 THEN 系统 SHALL 能把它转换为章纲、场景卡或正文片段。
4. IF 灵感与现有设定冲突 THEN 系统 SHALL 标记冲突并给出替代方案。

### 需求 8：Codex CLI 调用与任务模板

**用户故事：** 作为系统开发者，我希望每类写作任务都有稳定的 Codex CLI 调用模板，以便输出可控、可解析、可复用。

#### 验收标准

1. WHEN 系统调用 Codex CLI THEN 系统 SHALL 使用任务类型模板，如 outline.generate、chapter.plan、chapter.draft、selection.polish、continuity.check 和 idea.suggest。
2. WHEN 调用 Codex CLI THEN 系统 SHALL 注入项目上下文、目标文件、选区、相邻章节摘要、故事圣经和输出格式要求。
3. WHEN Codex CLI 返回结果 THEN 系统 SHALL 解析为结构化结果，包括正文、建议、风险、变更摘要和可应用补丁。
4. IF Codex CLI 调用失败 THEN 系统 SHALL 记录命令、退出码、错误摘要和重试建议。

### 需求 9：连续性检查与风险提示

**用户故事：** 作为长篇小说作者，我希望系统能检查前后矛盾、角色认知越界、伏笔遗漏和升级突兀，以便降低长篇失控风险。

#### 验收标准

1. WHEN 作者完成章节草稿 THEN 系统 SHALL 支持运行连续性检查。
2. WHEN 检查连续性 THEN 系统 SHALL 覆盖人物动机、时间线、地点、道具、能力、伏笔和 POV 边界。
3. WHEN 检查发现问题 THEN 系统 SHALL 按严重程度列出问题、原因和建议修复方式。
4. WHEN 没有发现明显问题 THEN 系统 SHALL 明确说明检查通过，并列出仍需人工确认的风险。

### 需求 10：用户界面与写作体验

**用户故事：** 作为小说作者，我希望界面像写作工作台，而不是普通聊天框，以便专注创作并快速调用 AI 功能。

#### 验收标准

1. WHEN 作者打开项目 THEN 系统 SHALL 显示章节树、正文编辑器、AI 操作面板和上下文面板。
2. WHEN 作者切换章节 THEN 系统 SHALL 自动加载章节正文、章纲、相关伏笔和人物状态。
3. WHEN 作者执行 AI 操作 THEN 系统 SHALL 显示任务状态、结果预览和可回滚操作。
4. WHEN 屏幕尺寸变化 THEN 系统 SHALL 保持编辑器可用，移动端至少支持查看、选择操作和轻量修改。

### 需求 11：文档与可执行任务保留

**用户故事：** 作为项目维护者，我希望需求、设计和任务拆分被保存成文档，以便后续实现时可以持续追踪。

#### 验收标准

1. WHEN 完成本次需求整理 THEN 系统 SHALL 保存 requirements.md、design.md 和 tasks.md。
2. WHEN 任务被拆分 THEN 系统 SHALL 每个任务都包含目标、产物、验收方式和关联需求。
3. WHEN 后续开始实现 THEN 系统 SHALL 可以根据任务文档逐项推进，而不需要重新理解完整需求。
4. WHEN 需求发生变化 THEN 系统 SHALL 支持修改需求文档并同步调整任务文档。
