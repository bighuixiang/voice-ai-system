# PlotPilot 学习化工作台显著改版 PRD

**Version**: 1.0  
**Date**: 2026-06-12  
**Author**: Sarah (Product Owner)  
**Quality Score**: 91/100  

---

## 1. 背景与目标

当前项目已经持续吸收 PlotPilot 的叙事运行时、上下文预算、AI 调用控制面、情绪账本、知识图谱、角色关系图、登场调度等机制。问题是这些机制多数以底层能力、局部面板或状态字段的形式落地，页面视觉和用户路径变化不够强，用户会感觉“学习了很多 PlotPilot，但页面变化不大”。

本需求的目标不是继续做零散功能，而是把“学习 PlotPilot”显性化为一个更强的工作台体验：作者打开章节后，首先看到当前章节的创作状态、风险、下一步动作、学习到的机制和这些机制对写作结果的影响。

一句话目标：把现有工作台从“模块集合”升级为“可观察、可推进、可学习的章节创作运行时”。

---

## 2. 问题定义

### 2.1 当前问题

- 页面新增了很多能力，但多数仍是面板堆叠，用户感知不到整体工作流升级。
- PlotPilot 学习成果散落在上下文装配、审计、任务历史、故事图谱等位置，没有统一解释“学了什么、用在哪里、产生什么价值”。
- 当前 `CreationLoopPanel` 已经具备闭环雏形，但视觉权重、信息密度和行动引导还不足以成为第一视口主体验。
- 用户需要自己判断下一步该保存、审稿、生成回顾、确认入账、检查关系图还是处理叙事债务。
- “页面变化不大”的本质不是缺少颜色或卡片，而是缺少一个强烈的、可操作的状态指挥台。

### 2.2 改版原则

- 少做装饰，多做状态投影。
- 少加独立按钮，多把能力串进当前章节下一步。
- 少展示技术名词，多展示机制价值和影响。
- 任何新增 UI 都必须回答：当前章节现在处于什么状态、为什么、下一步做什么。

## 3. 成功指标

### 3.1 主指标

- 作者进入项目工作台后，首屏即可识别当前章节状态、阻塞原因和下一步动作。
- PlotPilot 学习成果至少有 5 类机制在页面上被显性解释，并能跳转或定位到对应功能。
- `CreationLoopPanel` 从普通面板升级为首屏主控区，用户无需滚动即可看到核心状态。
- 至少 80% 的章节常用操作可以从“下一步动作”进入，而不是从多个面板中查找。

### 3.2 验收指标

- 在 1440px 桌面视口下，首屏必须出现：当前章节、运行时状态、下一步动作、闭环进度、至少 3 个风险/信号。
- 在 390px 移动视口下，首屏必须先显示章节状态摘要和主要行动按钮，闭环步骤可横向滚动或折叠。
- “PlotPilot 学习成果”区域必须展示：机制名称、已落地点、当前章节影响、对应入口。
- 页面不能只通过颜色变化体现改版，必须有信息架构变化和用户路径变化。

## 4. 用户画像

### 4.1 主要用户：长篇小说作者

- 目标：连续写作、保持设定一致、减少断更和返工。
- 痛点：章节多后容易忘记伏笔、人物状态、情绪债务和前文承诺。
- 期望：打开工作台后知道这一章还缺什么、下一章能不能安全推进。

### 4.2 次要用户：AI 写作流程设计者

- 目标：评估 PlotPilot 机制是否真正迁移到本项目。
- 痛点：底层实现已经很多，但缺少可演示、可解释的产品入口。
- 期望：能在页面上直接看到机制映射、运行状态和价值闭环。

## 5. 核心用户故事与验收标准

### Story 1：章节状态首屏可见

**As a** 长篇小说作者  
**I want to** 打开章节后立刻看到当前章节创作状态  
**So that** 我不用翻多个面板判断下一步做什么

**Acceptance Criteria:**
- 首屏顶部出现“章节运行时总览”，展示当前章节、字数、保存状态、审稿状态、回顾状态、入账状态。
- 总览必须给出一个主要下一步动作，例如“保存并运行章后流水线”“生成写作回顾”“确认情绪账本”“处理叙事债务”。
- 如果存在阻塞，必须显示阻塞原因和解除入口。
- 如果没有选中章节，必须显示选择章节或创建结构的入口。

### Story 2：闭环步骤成为主控路径

**As a** 作者  
**I want to** 按照结构、正文、审稿、回顾、账本、下一章的顺序推进  
**So that** 我能形成稳定的章节生产流程

**Acceptance Criteria:**
- `CreationLoopPanel` 需要升级为“章节闭环主控区”，每个步骤显示状态、指标、风险和动作。
- 步骤状态至少包含：未开始、进行中、已沉淀、阻塞、建议处理。
- 每个步骤只能暴露 1 个主动作，避免同一区域堆叠多个等权按钮。
- 点击步骤动作后应进入对应工作模式或触发已有 store action。

### Story 3：PlotPilot 学习成果显性化

**As a** 项目负责人  
**I want to** 在页面上看到我们从 PlotPilot 学到了哪些机制  
**So that** 我能判断学习是否真正转化为产品能力

**Acceptance Criteria:**
- 新增“PlotPilot 机制沉淀”区域，至少展示 5 个机制：
  - 叙事承诺锁
  - 上下文预算分层
  - AI 调用控制面
  - 情绪账本
  - 叙事债务/读者状态压力
  - 知识图谱/角色关系/登场调度
- 每个机制展示四类信息：来源机制、当前落地点、对作者的价值、跳转入口。
- 机制状态至少包含：已落地、部分落地、待增强。
- 页面文案必须偏产品语言，避免把源码路径作为主要展示内容。

### Story 4：下一步动作聚合

**As a** 作者  
**I want to** 系统告诉我当前最该处理的一件事  
**So that** 我不用在多个工具面板之间巡检

**Acceptance Criteria:**
- 新增“下一步动作”决策器，根据当前状态生成最多 3 个行动建议。
- 第一建议必须突出显示，并提供直接执行入口。
- 决策优先级建议：
  1. 未保存正文
  2. 章后流水线未运行或失败
  3. 回顾候选未确认
  4. 叙事债务过高
  5. 情绪账本存在未入账项
  6. 角色登场调度异常
  7. 可以安全进入下一章
- 每个建议必须显示触发原因。

### Story 5：风险与收益对照

**As a** 作者  
**I want to** 看到这些机制具体帮我避免了什么问题  
**So that** 我愿意按照闭环流程使用它

**Acceptance Criteria:**
- 新增“本章风险雷达”，展示叙事债务、连续性、情绪债务、角色覆盖、上下文截断、AI 调用健康。
- 每个风险项必须有状态、原因和建议动作。
- 对于已解决或正常项，展示“已沉淀”或“可继续”，避免页面只显示问题。

## 6. 功能需求

### 6.1 章节运行时总览

位置：工作台项目页第一视口顶部，替代当前较弱的普通面板开场。

内容：
- 当前项目名、章节名、文档类型。
- 当前字数、保存状态、最后保存时间。
- 当前写作模式。
- 运行时 fingerprint 或简化状态版本号。
- 闭环完成度，例如 `4 / 6 已沉淀`。
- 主行动按钮。

主行动按钮规则：
- 有未保存内容：保存正文。
- 已保存但章后流水线未完成：运行章后流水线。
- 有 recap candidate：确认写作回顾。
- 有叙事债务高风险：查看叙事债务。
- 无风险且当前章完成：进入下一章或创建下一章结构。

### 6.2 章节闭环主控区

基于现有 `CreationLoopPanel` 升级，而不是新增一个重复组件。

步骤：
- 结构：章节仪表盘、场景卡、结构反推状态。
- 正文：当前正文、未保存状态、AI 续写状态。
- 审稿：质量体检、张力、信息释放、宏观节奏风险。
- 回顾：写作回顾候选、章节摘要、事实补丁。
- 账本：情绪账本、伏笔、连续性、角色状态。
- 下一章：上下文装配、预算分层、承诺锁、可继续信号。

UI 要求：
- 桌面端 6 步横向一排或 3x2 紧凑布局。
- 移动端允许横向滚动，但单步卡片宽度固定，避免文本挤压。
- 阻塞、建议处理、已完成需要有明显不同的图标和边框状态。
- 每个步骤展示不超过 3 个信号，更多内容进入详情。

### 6.3 PlotPilot 机制沉淀面板

新增组件建议：`PlotPilotLearningPanel.vue`。

数据结构建议：

```ts
interface PlotPilotLearningItem {
  id: string;
  label: string;
  status: "done" | "partial" | "planned";
  sourcePattern: string;
  localLanding: string;
  userValue: string;
  entryAction?: CreationLoopAction | string;
  evidenceCount?: number;
}
```

默认机制：
- 叙事承诺锁：写作前约束主线承诺，避免早期泄底。
- 上下文预算分层：保护关键上下文，压缩低优先级材料。
- AI 调用控制面：记录 prompt version、变量计划、调用前检查。
- 情绪账本：沉淀人物伤口、馈赠、权力变化、开放回路。
- 叙事债务：识别未交付伏笔、风险、读者压力。
- 知识图谱：把事实、关系和章节证据投影为图谱。
- 角色关系与登场调度：发现缺少证据、长期未登场或近期过曝角色。

### 6.4 下一步动作决策器

实现位置建议：
- Store 计算属性：`nextWorkbenchActions`
- 类型定义：`WorkbenchNextAction`
- 展示组件：可放在运行时总览内，也可作为 `CreationLoopPanel` 顶部区域。

建议数据结构：

```ts
interface WorkbenchNextAction {
  id: string;
  priority: "critical" | "recommended" | "optional";
  label: string;
  reason: string;
  action: CreationLoopAction | string;
  targetPanel?: string;
}
```

### 6.5 风险雷达

风险来源：
- `currentRuntimeSnapshot.signals`
- `creationLoopSteps[].signals`
- `currentQualityReport`
- `currentSeriesQualityMetrics.narrativeDebtSignals`
- `storyGraph.characterRelations.appearanceSignals`
- `aiInvocations` 最新调用健康
- `savePipelineSteps`

展示规则：
- 首屏只展示聚合信号。
- 详情面板按类型分组展示。
- 所有风险项必须可追溯到具体来源或触发规则。

## 7. 非功能需求

### 7.1 性能

- 首屏新增计算必须基于已有 store 状态，避免额外阻塞请求。
- 图谱、审计、知识索引等重型能力不得在首屏同步重建。
- 计算属性应保持纯函数化，避免在渲染中触发异步副作用。

### 7.2 可维护性

- 优先复用现有 Pinia store、`CreationLoopStep`、`CreationRuntimeSnapshot`、`SavePipelineStep` 类型。
- 新增类型放在 `ui/src/types/novel.ts`。
- 新增 UI 组件放在 `ui/src/components/novel`。
- 不引入新的 UI 框架或图表库，除非后续图谱节点规模超过现有 SVG 能力。

### 7.3 设计约束

- 不做营销页，不做单纯介绍页。
- 不使用大面积渐变或装饰背景来假装变化。
- 首屏必须是实际工作台，而不是说明文档。
- 文案应短、硬、可执行，例如“回顾未入账”“上下文已截断 2 块”“建议先处理叙事债务”。

## 8. MVP 范围

### P0：显著改版必须完成

- 章节运行时总览。
- 升级 `CreationLoopPanel` 的信息结构和视觉权重。
- 下一步动作聚合。
- PlotPilot 机制沉淀面板。
- 风险雷达首屏聚合。
- 对应单元测试覆盖 store 计算逻辑。

### P1：增强体验

- 风险详情抽屉或可折叠详情。
- 机制沉淀面板支持按当前章节状态高亮“正在发挥作用”的机制。
- 角色登场调度与关系图在下一步动作中更精确排序。
- 审计报告中的 AI Control Plane 与首屏健康状态互相跳转。

### P2：后续演进

- 引入更强的图谱可视化能力。
- 为 PlotPilot 学习成果增加版本化路线图。
- 支持按项目类型自定义机制沉淀列表。
- 支持“本次写作会话复盘”：本次写作触发了哪些机制、保存了哪些状态。

## 9. 明确不做

- 不直接照搬 PlotPilot 的页面布局。
- 不引入完整自动驾驶或复杂状态机。
- 不让 AI 自动修改设定、账本或人物状态，仍保留作者确认门禁。
- 不把源码路径作为用户主要认知入口。
- 不为了视觉变化重写全局主题。

## 12. 风险与缓解
