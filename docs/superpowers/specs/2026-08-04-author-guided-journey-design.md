# 作者创作引导链路设计

## 目标与范围

本次先改造作者从录入原始想法到确认“一页故事蓝图”的完整体验。目标是让作者在任意时刻都能看到当前阶段、已经完成的内容、系统正在做什么，以及唯一明确的下一步操作。

本设计不改变既有的正文写作、质量评审和发布流程；这些后续模块将复用同一套阶段状态和主操作模式。

## 用户流程

1. **记录想法**：作者输入或补充故事想法，点击“保存想法”。界面分别反馈“未保存”“正在保存”“已保存”。
2. **整理素材**：系统保存输入后整理显式信息和待确认项。作者看到“已记录，正在整理重点”，无需判断是否需要冻结上下文或生成问题。
3. **补全设定**：系统一次只展示一个关键问题，显示“第 N/10 个关键问题”、该问题为何重要和当前回答框。作者确认回答后，系统保存回答并自动进入下一题。
4. **生成蓝图**：所有必答问题完成后，系统展示“信息已齐全，正在生成故事蓝图”。生成完成后进入蓝图确认页。
5. **确认蓝图**：蓝图以可编辑的一页摘要呈现。作者可直接修改、重新生成或确认。只有确认后，才提示进入大纲阶段。

作者在补全设定阶段仍可通过次要操作“补充想法”增加素材。系统明确说明补充素材会重新整理蓝图，已确认内容保留为参考；它不会静默覆盖作者已经确认的决定。

## 状态模型

前端引导状态从现有的创作会话、上下文快照、对话问题和问题回答中推导，不将展示状态作为独立事实源。状态包括：

| 状态 | 已完成 | 主提示 | 主操作 |
|---|---|---|---|
| `capture` | 无素材 | 请写下故事想法 | 保存想法 |
| `saving` | 素材待持久化 | 正在保存想法 | 等待 |
| `understanding` | 素材已保存 | 正在整理故事重点 | 等待 |
| `question` | 已冻结的理解快照 | 第 N/10 个关键问题 | 确认回答 |
| `answering` | 当前问题待写入 | 正在保存并准备下一步 | 等待 |
| `blueprint-generating` | 必答问题已完成 | 正在生成一页故事蓝图 | 等待 |
| `blueprint-review` | 蓝图已生成 | 请确认或修改故事蓝图 | 保存修改、重新生成、确认蓝图 |
| `ready-for-outline` | 蓝图已确认 | 故事蓝图已确认，可以开始大纲 | 开始制定大纲 |
| `blocked` | 上游信息不完整或操作失败 | 用中文说明原因和恢复方式 | 重试或返回对应步骤 |

每个状态都提供阶段编号、名称、状态标签、已完成数量和一条下一步说明。技术标识、内部指纹和冻结上下文只放在可展开的“处理详情”中，不能作为主流程信息。

## 界面设计

创作输入面板顶部新增固定的“创作进度”区：五个阶段按顺序展示，当前阶段高亮，已完成阶段显示完成标识，未开始阶段保持弱化。主区域只展示当前阶段所需信息和一个主按钮。

现有“回答当前问题”“生成唯一问题”“冻结完整原始输入”等重复或技术导向入口将被合并为状态驱动的唯一主操作。作者无需理解内部冻结、快照或问题生成的先后顺序。

补充想法、查看处理详情和重新生成属于次要操作，视觉上弱于主操作，且必须说明对已确认内容的影响。

## 数据与接口边界

后端保留现有原始输入、理解快照、问题事件和决策记录的不可变性。新增或扩展的引导投影只汇总它们，不改变既有事件的校验信息。

问题序列由后端权威维护。回答接口成功后，后端返回或前端重新加载当前引导投影，使下一问题与“第 N/10 项”来自同一事实来源。

故事蓝图作为独立的候选资产保存，须关联输入快照和已确认决定的指纹。编辑蓝图创建新的候选版本；“重新生成”不覆盖已确认版本；“确认蓝图”显式记录作者决定，并成为大纲候选生成的输入。

## 错误与恢复

所有错误向作者展示中文说明、失败发生在哪一步和可执行的恢复按钮。例如保存失败显示“想法尚未保存，请重试保存”；生成蓝图失败显示“蓝图尚未生成，已保留你的回答”，并提供“重新生成”。

发生输入变更导致上下文需要重整时，状态显示“素材已更新，需要重新整理”，主操作为“重新整理并继续”，不会静默跳转或让作者面对空白界面。

## 验收条件

- 作者录入、保存、整理、回答、生成蓝图和确认蓝图时，始终能看到当前状态及下一步。
- 同一时刻最多只有一个醒目的主操作。
- 确认一个问题后自动推进，并更新完成数量与当前问题。
- 完成必答问题后自动进入蓝图生成，不要求作者猜测下一步。
- 蓝图支持编辑、重新生成和确认，确认前不进入大纲。
- 现有历史英文问题、会话和事件仍可安全加载，并以中文作者文案呈现。
- 网络或上游失败时不丢失作者输入和已确认回答，且提供中文恢复操作。

## 后续扩展

故事蓝图确认后的大纲、章节写作、质量评审和发布阶段继续使用同一套“阶段进度 + 单一主操作 + 下一步说明”模式，但不在本次首段实现中重构其业务逻辑。
